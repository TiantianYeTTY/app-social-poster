# app-social-poster

> 给 App 截图，稳定产出一套可发社交平台的 3:4 竖版宣传图与配套发布文案（Agent Skill）。
>
> 从实机截图、手机边框素材与 App 定位出发，自动完成版式合成、文案起草、质检与交付，一次给出 4–6 张图、整套总览和一份 2 组（标题+正文）的发布文案。**去 AI 化视觉**（得意黑大字、白色贴纸、马克笔手绘线、手机微旋转、背景噪点）+ **防限流**（图与文案禁出现 APP / App Store / 下载等引流词）。
>
> 作者：**TiantianYe**
>
> 作者在 App Store 中的其他代表作品：水课帮-课堂提问助手；识词本-单词笔记；投影与视图3D教具；实验数据拟合；解构照片

## ✨ 这是什么

- 做 App 推广图时，最容易翻车的不是画图，而是反复返工：配色被否、阴影有硬边、标题里某个字显示错位、文案抄了参考案例、功能描述写错、**图带"AI味"**、**文案被平台限流**、**贴纸与下划线边缘锯齿**。
- 同一套图还要配一份能直接发的文案——只要标题和正文，话题标签用户自己打。
- 本技能将整个流程标准化：**素材实测 → 品牌与文案建档 → 图集生成 → 逐条质检 → 文案交付**。
- 首个落地案例是一套 6 张的课堂提问助手宣传图，脚本可像素级复现该定稿。

## 🎯 使用场景

| 要素 | 说明 |
| --- | --- |
| 前提 | 有 4–6 张 App 实机截图，最好附一张屏幕区透明的手机边框 PNG |
| 输入材料 | 截图、App 名称与正式定位、App 描述或功能清单；可选效果参考图 |
| 典型诉求 | 「做一套宣传图」「给这个 App 出小红书配图」「顺便拟标题和文案」「按上次那套再出一套」 |
| 质量要求 | 3:4 竖版、深蓝高饱和渐变+噪点、得意黑大字、白色贴纸、带边框实机截图、柔和阴影、**边缘光滑无锯齿**、**无 AI 模板感**、文案抓人且功能准确、**无限流词** |

典型触发指令示例：

> 给你几张新 App 的截图，按 app-social-poster 出一套宣传图，顺便把发布文案写好。

## 🚀 使用方法（工作流概览）

| 阶段 | 内容 | 关键点 |
| --- | --- | --- |
| Stage 0 | 盘点素材、量尺寸、实测边框屏幕透明区 | 屏幕矩形必须像素扫描实测，禁止照抄 |
| Stage 1 | 写 `config.json`：品牌、正式名称、主色、版式 | 正式名称唯一，营销别称不得拼成产品名 |
| Stage 2 | 写图上大字/贴纸词与 2 组发布文案 | **先过防限流 grep**；参考案例只学结构；功能描述以用户定稿为准 |
| Stage 3 | 跑脚本出图 | 整行绘制文字、单层带 pad 高斯阴影、手机微旋转、**4× 超采样边缘抗锯齿** |
| Stage 4 | 六步质检 | 目视 + 像素采样 + 红线 grep（含限流词）全部归零 |
| Stage 5 | 交付图集、总览、文案与日志 | 定稿只读，新 App 写新目录 |

### 输入 / 产出

```
App 实机截图 (4–6 张)  ─┐
手机边框 PNG (可选)     ├─→  01..0N  宣传图 PNG (2160×2880, 3:4)
App 名称 / 定位 / 描述 ─┘      00_整套总览.jpg
                              发布文案.md（2 组：标题+正文）
```

## 🔧 环境依赖

- Python 3 + Pillow：用于图像合成、圆角遮罩、渐变背景、噪点与高斯阴影。
- **得意黑 Smiley Sans**（`~/Library/Fonts/smiley-sans-v2/SmileySans-Oblique.ttf`）：v2 主字体，社媒设计常用、自带倾斜；缺字体请先安装，不要退回系统黑体。
- macOS 系统字体 `Hiragino Sans GB`：备用中文字体。
- `sips` 或 Pillow：量取截图尺寸、验证 macOS 原生解码链。
- `qlmanage`（可选）：刷新缩略图缓存，解决 Finder 预览异常。

## ⚠️ 重要说明

1. **定稿交付物只读**：换 App 一律新建输出目录，不覆盖已认可的成品。
2. **防限流**：图上与文案禁出现 APP / App Store / 下载 / 链接 / 安装等字样，否则会被平台判站外引流限流；宣传只做三件事——钩子抓眼球、报品牌名、讲核心功能。
3. **去 AI 化**：不用系统黑体模板、无序号、无光晕、无罗列式副标题；用得意黑 + 贴纸 + 手绘线 + 微旋转 + 噪点。
4. **别人的参考案例只学结构与语气，禁止照抄原句**；用户自己重写的文案是权威基准，AI 不得改写其中的功能词。
5. **功能描述必须逐条核对**，尤其是提醒方式、AI 用途；不确定的功能宁可不写。
6. 全部文字纯白，品牌只出现在左上角贴纸；不加副名、不加英文、不加 emoji（除非明确要求）。
7. 主标题必须整行一次绘制，逐字符绘制会让「一 / 二」这类扁字变成上划线。
8. 阴影必须先给 alpha 四周留透明边再模糊，否则边缘会被硬裁断。
9. 未获明确指令不擅自对外发布任何内容。
10. 贴纸与下划线一律 4× 超采样出图；1× 硬边绘制会产生可见锯齿，透明层须预填白色避免暗边。

## 🐛 已知踩坑点（节选）

- 逐字符绘制中文标题 → 「一」被顶到字格顶部变成上划线；改成整行一次绘制。
- 在手机原尺寸上直接高斯模糊 → 阴影四边硬切断；先留 `blur×3.2` 的透明边再模糊。
- `composite_at` 系函数返回值没接收 → 贴纸/手机**静默丢失**；必须 `im = xxx(...)`。
- 背景噪点叠加 offset 写错 → **整图变纯黑**；对称写法 + 出图后采样四角像素验证。
- 图与文案带 APP / 下载等字样 → 平台判站外引流**限流**；发布前 grep 归零。
- 视觉带序号/光晕/系统黑体模板 → 用户一眼识别"AI味"被整体否决；用去AI化六件套。
- 边框自带灵动岛 + 截图自带灵动岛 → 双岛错位；按截图类型选择清岛后的边框。
- 反复覆盖同名文件 → Finder 缩略图缓存抓到半成品帧变纯黑；清缓存并原子重写文件即可，不是图片损坏。
- 贴纸/下划线在 1× 下硬边绘制 → 放大全是阶梯毛刺；4× 超采样 + LANCZOS 缩回，透明区预填白色。
