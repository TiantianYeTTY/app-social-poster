# 多 APP 档案与建档模板

用户明确希望：以后只要给**任意 App 的截图 + 调用本 skill**，就能稳定产出同样质量的宣传图和文案。
已点名的 App：水课帮、识词本、实验数据拟合、投影与视图3D教具、解构照片（"等等"还包含
ShellShot 等）。

## 一、已知 App 名单与正式名称

| App | 正式名称（写入文案，不印图上） | 品牌条只印 |
|---|---|---|
| 水课帮 | 水课帮 - 课堂提问助手 | 水课帮 |
| 识词本 | 识词本 - 单词笔记（待确认） | 识词本 |
| 实验数据拟合 | 实验数据拟合（待确认定位） | 实验数据拟合 |
| 投影与视图3D教具 | 投影与视图3D教具（待确认定位） | 投影与视图3D教具 |
| 解构照片 | 解构照片（待确认定位） | 解构照片 |
| ShellShot / 带壳截图 | 带壳截图（待确认定位） | 带壳截图 |

**"待确认"是硬要求，不是客套**：定稿只验证了水课帮，其余 App 的正式名称、目标人群、
核心卖点**不得凭记忆或猜测填写**。使用前按下方"三问"确认一次；用户不回复时，只从
截图可见的 UI 文案与随附的 App 描述里提取，写不出就不写。

## 二、建档三问（缺什么问一次，禁止编造）

1. **正式名称**：`品牌 - 定位` 怎么写？（决定文案里的唯一名称，防混淆）
2. **目标人群 + 最痛的瞬间**：谁会用、什么场景下会掏出手机？（决定 01 钩子与金句）
3. **3–6 个真实卖点**：从 App 描述或截图 UI 来，逐条可核对。（决定 ①②③④ 清单与 6 张副标题）

用户只丢截图不给描述时：从截图里的按钮、标题、列表文字提取卖点，
并在交付说明里标注「卖点来自截图可见文案，未覆盖的功能未写入」。

## 三、主色策略

- 用户**未指定主色** → 一律沿用定稿高饱和蓝 `(30,126,244)→(8,74,202)`，
  并在交付说明里写一句「主色沿用品牌蓝，如需换色请说明」。
- 用户给了**效果参考图** → 用 Pillow 采样其背景四角，把结果写进 `colors.top/bottom`；
  但饱和度与深度仍按定稿口径（更深、更饱和），不要照抄浅天蓝。
- **禁止**自作主张给不同 App 换色系（红/绿/紫），除非用户明确要求。

## 四、`config.json` 字段速查

| 字段 | 含义 | 缺省 |
|---|---|---|
| `app_name` | 品牌条文字（唯一，图上只出现它） | 必需 |
| `official_name` | 正式名称，仅用于文案与自检 | 必需 |
| `src_dir` / `out_dir` / `frame_path` | 素材目录 / 输出目录 / 边框 PNG 绝对路径 | 必需 |
| `canvas` / `margin` | 画布与左边距 | `[2160,2880]` / `140` |
| `colors` | `top` `bottom` `glow` `rings` | 定稿蓝 |
| `font` | `path` `bold_index` `regular_index` | Hiragino Sans GB / 2 / 0 |
| `layout` | 品牌、两行标题、短线、副标题、手机顶部的 y 与字号 | 见 `design-spec.md` |
| `frame` | `size` `screen_box` `screen_radius` `island_clear` | 必须用 `pipeline.md` 的扫描法实测 |
| `shadow.layers` | 双层高斯参数 `[blur,opacity,dx,dy,[r,g,b]]` | 定稿两层 |
| `footer_lines` | 收尾卡两行（品牌金句 / 署名） | 可选 |
| `posters` | 4–6 张：`name` `shot` `keep_island` `l1` `l2` `sub` `width` `dx` `footer` | 必需 |

完整可复制样例：`../examples/config.example.json`。

## 五、换 App 时的检查顺序

1. 新 `out_dir`，**不碰水课帮定稿目录**（红线 #13）；
2. 实测新边框素材 `screen_box`（不同机型几何不同）；
3. 每张截图判断是否自带灵动岛 → 填 `keep_island`；
4. 文案先过 `copywriting-playbook.md` 的品牌红线与禁用表达；
5. 跑脚本 → 走 `pipeline.md` 五步质检 → 写 `发布文案.md` 七节；
6. 交付后在工作区 `.workbuddy/memory/` 追加日志。
