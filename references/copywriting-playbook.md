# 文案方法论（用户最不满意的一块，三条红线逐条遵守）

## 〇、三条最高权重红线

### A. 品牌用词红线

> 用户原话：「然后06你的宣传语不对：我们是"水课帮-课堂提问助手"，不要写"听课助手水课帮"之类，容易产生混淆。」

- **正式名称唯一**：`水课帮-课堂提问助手`（其他 APP 见 `app-profiles.md`，一律「品牌-定位」）。
- 图上品牌条**只印 `app_name`**（如「水课帮」），不印定位、不印英文、不印别称。
- 「大学生上课摸鱼助手」「听课助手」「防止课堂提问」「再也不怕被点名」是**营销钩子**，
  只能出现在标题、口语、话题标签里。
- **禁止**把钩子与品牌拼成产品名式组合：`听课助手水课帮`、`水课帮听课助手`、
  `摸鱼助手水课帮`。生成后 grep 归零。
- 副标题里要用品牌就只写「水课帮 · ……」。

### B. 原创红线：别人的案例只学「意思」，禁止照抄

> 用户原话（第 5 轮）：「我给你是看意思、看宣传文案，但是你直接照抄，效果很不好。」

用户提供的参考案例是**别人写的小红书文案**，用途只有三个：
① 学结构；② 学语气；③ 学「功能点怎么写成人话」。
**不是**可以复制的文案库。

曾犯的错：把案例整句搬进产出——
「把上课交给 AI，把时间还给自己」直接印到 06 图上当主标题，
「站起来脑子空白」做 04 主标题，「谁懂啊」「线下课实时收音」「一键开始摸鱼」
「终于不再担心随机点名回答了」「做了个防止课堂提问的小软件」出现在标题备选里。
用户判定为照抄，要求返工。

**可执行验证**（生成文案后必做）：
1. 把用户提供的案例拆成 `_banned_phrases` 清单，逐条 `grep -F` 比对标题、
   主副标题、正文、金句；**命中即重写**。禁用短语见下方清单。
2. 每条主标题/金句必须能用本 App 的真实功能点重新解释一遍；解释不出来就是抄来的空话。
3. 用户**点名要的钩子词**（「大学生上课摸鱼助手」「再也不怕被点名」等）可以单独使用，
   但不得与案例原句拼成整句，也不得把案例标题改两个字当自己的。
4. 案例原文**不要整段贴进 skill 或公开仓库**（版权 + 观感），只保留短语级禁用清单。

**禁用短语清单**（来自用户第 3 轮提供的两条案例，仅用于比对，禁止写进产出）：
`终于不再担心随机点名回答了` / `大学生水课摸鱼助手上线` / `实时语音识别捕捉老师上课重点`
/ `出现点名就红灯预警` / `AI帮你迅速回答没听到的问题` / `课后不再错过重要作业/小测通知`
/ `只需要把电脑麦打开` / `一键开始摸鱼` / `把上课交给AI，把时间还给自己`
/ `做了个防止课堂提问的小软件` / `听课助手内测招募` / `谁懂啊` / `线下课实时收音`
/ `自动生成简短可直接口述的回答` / `支持普通话线下课堂`。

### C. 用户自己重写的定稿 = 权威基准（与 B 不冲突）

> 用户原话（第 6 轮）：「而且其实你的宣传文案有些功能性描述是错的：我重写了一下……你参考一下」

用户**亲自重写**的文案是产品作者定稿，可以直接用（即使个别句子与案例相似，
因为已经过用户改造与认可）。但 AI 不得自行改写其中的功能词。

**功能点必须以用户定稿为准，逐条核对，禁止 AI 自行"优化"**：

| 我曾写错（禁用） | 用户定稿（正确） |
|---|---|
| 实时收音识别课堂重点 | 实时课堂识别，自动把老师抛出的问题单独捞出来 |
| 灵动岛 + 小组件 + 震动提醒 | 灵动岛 / 实时活动 / **通知提醒** / 震动提醒 |
| 没听清的题，一键交给 AI | **不会做的题**，一键交给豆包、千问，答案直接铺在屏幕上 |
| 中英双语识别 + 课堂记录智能分段、补标点 | 中英课堂都听得懂，**英语听说课也不怕** |
| iPhone / iPad / Mac / Apple Watch | iPhone / iPhone Duo / iPod / iPad / Mac / Apple Watch / Apple Vision Pro |
| 额外加「默认识别在设备端、不保存音频」 | 用户定稿**没有**隐私句 → 不写（图片更早也已被要求不谈隐私） |

判断口诀：**案例只借结构，功能只认用户**。功能描述不确定时问一次，不要从案例里
"顺"一个听起来差不多的说法（例如案例说"自动生成一句话答案"，我们不能写成 App 自带生成）。

## 一、爆款结构（只学骨架，不抄句子）

1. **人群 + 身份钩子**开头（大学生 / 上课摸鱼助手），不是产品功能名；
2. **一个具体到画面感的痛点瞬间**（低头记笔记被点名、不知道老师刚问了什么）；
3. **1、2、3、4 功能清单**，每条一句、动词开头、说人话；
4. **一句金句收尾**（用户定稿：`把上课交给「水课帮」，把时间还给自己`）；
5. 语气口语、短句、有情绪（专治 / 再也不怕 / 剩下的交给它）。
6. **默认不用 emoji**；用户明确要小红书排版版时，另出一版，不混进图片。

## 二、6 张图的叙事模板（定稿版，主标题 = 钩子，副标题 = 功能）

| 位 | 作用 | 定稿主标题 L1 / L2 | 定稿副标题 |
|---|---|---|---|
| 01 | 首图钩子 | 大学生 / 上课摸鱼助手 | 再也不怕老师随机点名提问 |
| 02 | 上手动作 | 一键开始 / 剩下的交给它 | 实时课堂识别，老师问了什么自动捞出来 |
| 03 | 提醒场景 | 点名一来 / 手机先知道 | 灵动岛 / 实时活动 / 通知提醒 / 震动提醒 |
| 04 | 最痛瞬间 | 点名点到我 / 答案已经在了 | 不会做的题，一键交给豆包、千问 |
| 05 | 差异化 | 中英课堂 / 都听得懂 | 英语听说课也不怕，提问还有震动提醒 |
| 06 | 金句收尾 | 你在走神 / 它替你听着 | 水课帮 · 提问、答案、提醒全都有 |

- 每行 ≤8 字，副标题 ≤22 字且只占一行（超出会压到手机）。
- 主/副标题**必须是原创或用户定稿**，不得出现禁用短语清单里的句子。
- 收尾卡不写隐私；隐私也不写进发布正文（用户定稿已删）。
- 主标题里出现「一 / 二」没问题，前提是整行绘制（错误档案 #5）。

## 三、`发布文案.md` 七节模板（定稿结构，逐节照写）

```
# <APP> · 社交媒体发布文案（用户定稿基准）
配套图片：01–06，2160×2880（3:4），按编号发布，首图用 01。
**正式名称：<品牌-定位>**；营销钩子（只用于标题/口语/话题标签）……
> 主推正文以用户重写版为准；参考案例只学结构，案例原句不进产出。

## 一、标题备选（挑一个用）      # 6 条，表格：痛点/直给/场景/功能/双语/用户定稿句
## 二、主推正文（可直接复制）    # 痛点瞬间 → 正式名称 → 1、2、3、4 清单 → 金句 → 完整平台列表
## 三、短版正文（朋友圈/微博）
## 四、话题标签                  # 10–12 个，注明挑 6–8 个
## 五、评论区第一条
## 六、6 张图分别讲什么          # 表格：图 / 主标题 / 对应卖点
## 七、发布小提示                # 功能描述以本文件为准、原创红线、品牌红线、不写价格/链接
```

**主推正文直接用用户定稿**，不要另写一套；AI 只负责补标题备选、短版、标签、
评论区、逐图说明和发布提示。定稿全文放在本次交付目录的 `发布文案.md`，
skill 内只保存上面的功能点映射表，避免公开仓库里堆营销正文。

## 四、禁用表达清单

- 并列功能短语当标题（「实时记录 · 自动提取 · 随时回溯」）→ 平淡，已否决。
- 「保护隐私 / 不存录音 / 不上传第三方」当任何一张图的主卖点，或写进发布正文 → 已否决。
- 价格、上架状态、下载链接、内测招募等图中未出现的信息 → 放评论区，避免判硬广。
- 编造功能（自动点名红灯预警、自动生成口述答案、作业小测通知）→ 描述里没有就不写。
- 案例原句、案例标题的微调版 → 见 §〇-B 禁用短语清单。

## 五、换 APP 时的文案适配

1. 换**人群**与**痛点瞬间**，骨架不变；
2. 1、2、3、4 换成该 App 的真实卖点，逐条对 App 描述或用户定稿核对；
3. 金句重写，别复用「把上课交给……」；
4. 正式名称换新 App 的「品牌-定位」，营销钩子单独列，**永不与品牌拼接**；
5. 用户提供了自己写的文案时，**以用户文案为准**，AI 不得改写功能词；
   用户只提供别人案例时，**只学结构**，逐句过禁用清单。
